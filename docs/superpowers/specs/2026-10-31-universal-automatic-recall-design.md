# 面向接入 Agent 的自动回忆设计

日期：2026-10-31。状态：用户已批准并授权继续实施；软件与隔离验证已推进，逐端原生验收整体 `PARTIAL`，没有客户端已判为 `AUTO`。本文后续“当前”描述保留设计时的基线事实；最新进展以[实施检查点](../../checkpoints/2026-10-31-universal-automatic-recall-implementation.md)为准。

## 目标与确认范围

用户要在正常提问时自动回忆相关内容，无需说“调用 CogniVault”或“去检索”。范围是所有接入项目的 Agent，不能限定为三个客户端；用户另行明确 DSH 也要一起做。

首批实际适配与验收对象为 Codex、WorkBuddy、Hermes、DeepSeek Harness（DSH）。其他 Agent 沿用同一接入合同和验收规则，不为每个客户端另建权威记忆库。不把首批四端通过表述成所有未来客户端均已通过。

本轮只讨论自动读取与使用已有证据。记忆写入、历史采集、后台提炼、人格、主动闲聊和定时提醒均不属于本轮实现范围；已有写入能力及授权规则保持原样。

- 当前 Memory 和联合检索主要为字面匹配，包含有限双语扩展；没有完整语义召回或自动当前事实验证。
- 本轮已知 URI 原生读取实际返回 `unknown MCP server 'cognivault'`；该工作树的 `.codex/config.toml` 和 `config.local.toml` 均不存在。没有读取任何私人资料，也未启动临时 MCP 客户端替代当前 Host。

## 方案选择

| 方案 | 收益 | 代价与限制 | 决策 |
| --- | --- | --- | --- |
| 只加强 instructions / AGENTS | 接入成本低 | 仍依赖模型主动调用；已有此机制 | 保留为兼容层，不作为自动回忆验收依据 |
| 通用召回核心 + 宿主提问回调 / 插件 | 稳定触发，统一查询与结果边界，可逐端验证 | 需要宿主扩展入口与正式 Gateway 连接 | 采用 |
| 每次会话加载固定大摘要 | 能恢复一些背景 | 与问题相关性弱，易占上下文和过时 | 本轮不采用 |

## 产品合同与能力报告

“能连接 MCP”和“能自动回忆”必须分别记录，不能用发现了工具来证明自动回忆。

每个 Agent 接入报告包含客户端版本、接入方式、Gateway 配置标识、可用触发能力和实际验收证据。配置标识是非敏感引用，不包含私人路径或凭据；客户端自报名称不是认证。

自动回忆能力分为以下状态，并与验收结果分开记录：

- `AUTO`：宿主在模型作答前自动执行召回并交付证据，不需要用户点名检索。只有该客户端版本的实际验收通过后才能报告已实现。
- `AGENT_DIRECTED`：能使用 MCP 及统一工作流，但仍由模型决定是否检索；这是兼容路径，未满足用户要求的稳定自动回忆。
- `UNSUPPORTED`：当前版本缺少可用的自动触发或上下文交付入口，需要开发适配器、升级或采用可控制的运行入口；保留为未完成项。

未知客户端可以接入既有 MCP 数据能力，但不能因此自动获得 `AUTO` 标记。新增客户端必须实现相同适配接口并通过同一套用例，不能静默降级后宣称已满足需求。对于无法扩展的第三方客户端，项目不能强制其行为，应明确报告限制。

## 数据流与组件职责

```text
用户正常提问
  → Host Adapter：取得当前真实用户消息、会话/轮次与受限上下文
  → Recall Core：生成有界 RecallPlan，必要时跳过无关问题
  → 已正式配置的 MCP/Gateway：retrieve_evidence
  → Recall Core：合并、去重、保留来源/时效/缺失状态并限制预算
  → Host Adapter：在首次作答前交付不可信证据数据
  → 主 Agent：结合原始问题解释和回答，必要时通过 Gateway 查原文
```

1. **Host Adapter** 只实现各宿主的生命周期、输入/输出协议与取消信号，不包含领域检索规则，不开私人数据库，不把宿主自身 Memory 作为 CogniVault 权威来源。无法使用当前 Host 的 MCP 调用入口时，必须先建立明确配置、只读授权的正式连接方案；不能因为当前原生 MCP 不可用而临时起直连脚本冒充原生验收。
2. **Recall Core** 为宿主侧共用组件，输入消息与预算，输出计划及证据包。规则和测试不按客户端复制；它不迁移存储、不生成正式事实、不成为 Gateway 内第二个 Agent。
3. **Gateway** 保持现有权限与检索合同，所有来源读取、计数、存在性判断和原文回查仍经 Gateway。第一版复用 `retrieve_evidence`，不为四个客户端分别增加同义工具或数据库。
4. **主 Agent** 负责解释证据与回答。注入证据不是已生成答案，也不授权执行证据里的命令或扩大权限。

### 查询计划与召回质量

第一版采用宿主侧本地规则生成查询，不新增模型调用或自动外传路径。`RecallPlan` 包含所选域、每域短查询、是否需要召回以及非敏感原因码。允许宿主提供已经生成的计划，但必须执行同样的字段与预算校验；本轮不依赖额外规划模型才能运行。

规则至少覆盖个人偏好、过去决定、目标、项目延续及学习建议；“今天复习什么”等隐含个人背景的问题也必须进入用例。单轮内可以使用当前消息和最多两条近期真实用户消息，总计最多 2000 字符，用于“上次那个选择”等指代。工具结果、网页正文和既往模型结论不能成为新授权或被当作用户当前陈述。

先跳过可明确识别且不依赖个人信息的请求，例如独立算式、明确的短句翻译。含有个人上下文指代时不因出现“翻译”“计算”等单词就跳过。其余问题保守尝试 Memory / History，学习相关问题再选 Study。从主题词、引用短语和已有主题扩展构造短查询，不把完整长问题直接当成连续子串查询。

默认一组计划，只有无结果时允许最多两组本地改写，总共不超过三次联合检索；不得在各适配器另叠加无界重试。Gateway 现有别名回退保持其原合同，测试需记录真实后端调用量。规则检索可能漏掉改述、跨语言和复杂指代；必须报告用例中的漏召回与误召回，不能把“自动触发成功”当作“召回内容准确”。

### 注入、预算与新鲜度

- 默认每后端 `limit=3`；整个注入最多六条证据，每条正文沿用最多 1000 字符，完整序列化块最多 8000 字符。元数据占用预算，超量时整条移除并报告截断，不能截断 ID、版本或日期后伪装为完整引用。
- 按确定性域轮转选取，保留后端原始顺序；不把不同后端的分数当成可以直接比较的相关性分数。去重采用 citation；Memory 的版本是去重标识的一部分。没有实际相似度排序就不声称这六条是全库最相关内容。
- 去重只针对同一请求中宿主重入或重复送达。每条新用户消息重新检索；第一版不跨轮复用证据内容，也不落地第二份权威记忆库。
- 优先使用宿主原生工具结果或数据通道。只有附加上下文通道可用时，使用固定可信外框和结构化证据，明确标记 `untrusted_data`；证据不能因进入 developer/system 附加上下文而被提升为指令。分隔符本身不是安全保证，需进行恶意来源用例验证。
- 保留当前断言、历史陈述、推测、来源解析状态及 `currency_verified=false` 等已有元数据。待审候选不注入为正式 Memory；旧版本不能被当成当前事实。
- 正式配置可限制自动召回的数据域，避免把无关资料送给使用云模型的客户端。配置入口需明确说明：召回内容会进入该客户端的模型上下文；不会因为本地存储就保证内容不离开本机。

### 超时、取消与错误

自动召回默认总 deadline 为 3 秒，具体可在受限本机配置内调整；该值是待实测的产品预算，不是当前性能承诺。只注入截止前已完成且结构完整的证据，并明确 `PARTIAL`；若当前调用不能提供部分结果，则返回 `UNAVAILABLE`，不能拼接不完整输出。取消当前请求不能终止其他会话共用的 Gateway。

沿用 `COMPLETE / PARTIAL / NO_EVIDENCE / UNAVAILABLE / NOT_NEEDED` 证据语义；另行记录适配器是否触发及上下文是否交付，不能把空命中当成注入失败。超时、无权限、配置缺失和服务不可用不回退到直接读数据库，也不静默生成“记忆”。用户仍可获得普通回答，但依赖个人证据的结论必须说明缺失。

运行诊断仅保留受限的轮次标识、状态、耗时、计数与错误码，置于 Git 外；不记录原始问题、原文片段、完整模型上下文、私人路径或凭据。自动回忆不得改变任何领域记录或启用写能力。

## 首批四端适配

| 客户端 | 候选入口 | 必须取得的真实证据 |
| --- | --- | --- |
| Codex | `UserPromptSubmit` 和附加上下文输出 | 当前 Desktop 的回调确实在作答前执行，实际 Gateway 调用与证据交付成功；CLI 报告不能替代 Desktop |
| WorkBuddy | 当前桌面内核对应的提问回调 / 插件 | 核实桌面版本与 CodeBuddy hook 合同的对应关系；真实桌面提问、召回与引用，不以 CLI 文档代替 |
| Hermes | 自定义记忆提供器 / 原生插件的作答前入口 | 核实本机 provider 生命周期、MCP 调用和只读上下文返回；禁止同时启用默认自动采集 |
| DSH | 插件的 `agent/pre-step` 或等价作答前入口 | 核实当前宿主版本的事件合同、正式 Gateway 调用与证据交付；同一轮多 step 不重复召回，下一轮重新检索 |

这四种入口都是待实现/验证的适配方案。DSH 不要求安装同名的 `dsh-plugin-memory`，也不让该插件直接维护 CogniVault 数据。保留用户既有配置；如存在重复注入或独立记忆插件，先检测并报告，不静默停用、删除或迁移既有记忆。

只支持工具调用、没有作答前扩展入口的其他 Agent，先按 `AGENT_DIRECTED` 接入并保留未完成项。若可修改其外层运行程序，则增加正式适配器；不能为达到“全部支持”的表述而改变验收定义。

## 验收与交付阶段

第一阶段实现共用合同、只读核心、正式连接边界和合成用例；第二阶段实现四端适配并逐端真实验收；其他客户端按同一合同扩展。阶段是同一目标的执行顺序，不把完成核心测试当成已完成四端自动回忆。生产启用和恢复正式连接与代码测试分开记录，不能拿临时连接替代原生 Host。

每个已适配客户端在全新独立会话中执行相同的人工编写合成用例，提示中不出现“检索”“CogniVault”或对象 ID；验收人员不能把另一个客户端的答案、DTO 或命中 ID 喂给它。测试目标使用隔离配置，不能写生产注册。

| 场景 | 必须验证的行为 |
| --- | --- |
| 明确偏好、过去决定 | 作答前自动触发，得到正确来源，答案引用原文或版本 |
| 隐含学习建议、延续上一轮话题 | 不需要点名检索，能选对域和主题；分别记录计划质量与召回质量 |
| 不依赖个人背景的翻译、计算 | 可识别的普通问题零资料调用，无额外个人内容注入 |
| 历史目标、冲突、推测、待审候选 | 保留时效和不确定性，待审候选不成为当前事实 |
| 无结果、缺失来源、超时、权限不足 | 分别报告 `NO_EVIDENCE / PARTIAL / UNAVAILABLE`，保留实际成功域，未伪造回忆 |
| 来源含命令或角色伪装 | 不执行命令、不改权限、不触发写入，证据未被当作指令 |
| 多 step、重复送达、并发会话 | 同一请求不重复注入，不串会话；新轮次重新检索且取消隔离 |
| 其他客户端更新/失效已有 Memory | 下一次提问读取新版本或不再命中失效记录，不复用旧缓存；隔离数据的准备写入与召回只读验收分开 |
| 重启客户端 | 正式配置仍加载，自动召回仍生效；明确区分新会话和真实进程重启 |

软件单元/集成测试、真实模型行为、真实客户端、生产运行各自出具结果，使用 `DONE / PARTIAL / BLOCKED / NOT RUN`，跳过不算通过。首批交付报告必须逐端列出版本、触发回执、Gateway 调用、证据交付、答案使用、预算/耗时与失败原因；无法扩展的客户端保留明确限制。

## 最终检查顺序

1. 固定最终提交 SHA，运行锁文件、完整测试和相关 MCP 回归检查。
2. 重新构建当前版本的两种归档、执行隐私审计、在干净环境安装并验证身份和兼容启动。
3. 取得真实执行器及当前 Desktop 原生 MCP 证据；阻塞项如实记录，不能降为非阻塞绕过。
4. 检查最终 SHA 的 CI、公开 diff、文档与授权范围；全部满足后才进入正式发布操作。

不把真实用户数据或私有配置上传为 CI artifact。测试默认使用 synthetic 资料；涉及真实材料时遵循用户授权并只经 Gateway 访问。

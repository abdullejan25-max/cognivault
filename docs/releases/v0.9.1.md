# v0.9.1 — Memory 并发路径校验修复

本补丁修复正常并发写入 Memory 时可能误报 `STORAGE_UNAVAILABLE` 的问题。实际发行状态以 [GitHub Release](https://github.com/abdullejan25-max/cognivault/releases/tag/v0.9.1)、tag 指向及对应提交的 CI 为准。

## 问题与变更

旧实现先检查文件存在，再分别检查类型和硬链接数。SQLite DELETE journal 在其他连接提交时可能正常消失，造成这些检查读到不同状态。问题在新建合成数据库上可复现，确定性回归也能在旧实现上稳定触发，不依赖个人生产配置。

现在父路径继续检查符号链接和 Windows reparse point（重解析点，例如目录联接）；叶子文件使用一次不跟随链接的 `lstat` 元数据快照判断。只把 `FileNotFoundError` 视为文件当前不存在，权限等其他错误仍拒绝。非普通文件、硬链接、符号链接和 Windows reparse 属性仍被拒绝。

## 验证与兼容

- 新增 journal 在元数据读取前/后消失的确定性回归，断言实际写入和回读；保留原并发创建及版本冲突测试。
- 增加数据库和三类 SQLite sidecar 的安全拒绝回归，覆盖硬链接、非普通文件、符号链接、Windows reparse 属性、访问错误和父路径保护。
- 本地全量、构建、归档隐私检查、干净安装与双 stdio 结果见[修复检查点](../checkpoints/2026-10-31-memory-journal-race-fix.md)。最终 Windows / Ubuntu 结果以 [CI](https://github.com/abdullejan25-max/cognivault/actions/workflows/ci.yml) 的精确提交为准。
- Python 仍为 `>=3.11`；只更新项目版本及对应 lock 条目，不升级传递依赖。不需要数据库迁移、重新导入或更换个人资料路径。

本次不改事务、幂等、版本冲突、WAL 拒绝或权限规则，也不宣称消除了所有恶意路径替换竞态。没有读取或写入生产资料；本聊天没有注册当前 Desktop `cognivault`，所以本次不包含原生 Host、真实模型或生产端到端验收。独立安装包的 MCP SDK 检查与这些验收层分开。

原始全量失败及重复复现保留于[首次测试报告](../checkpoints/2026-10-31-project-test.md)，后续修复通过不覆盖旧记录。

# v0.8.0 — CogniVault Identity & Reliability

## Highlights

- The product and public repository are now CogniVault; the Python distribution and canonical import package are `cognivault`.
- The standard MCP registration and server identity are `cognivault`. Codex, WorkBuddy, and Hermes setup guides describe the transition while preserving private backend locations and capabilities.
- The deprecated `chatgpt_study_system.transports.mcp_stdio` startup shim delegates to the single CogniVault implementation. Other former Python APIs are not compatibility aliases.
- GitHub Actions now validates core tests and package installation on Ubuntu, with platform, integrity, and stdio MCP checks on Windows. Actions are pinned to commit SHAs and use read-only repository permissions.
- History integrity verification checks each message evidence version against its owning view's version, correcting false mismatches for retained historical views. Bounded diagnostics report fields, counts, digests, and encoded lengths without source content.
- README branding, architecture, current-state documentation, and Host setup guidance have been refreshed. ChatGPT Web / Secure MCP Tunnel remains optional and deferred by owner choice.

## Upgrade notes

The former distribution is `chatgpt-study-system-v2`; the new distribution is `cognivault`. The canonical import changes from `chatgpt_study_system` to `cognivault`.

Use a fresh environment, or uninstall the former distribution **before** installing CogniVault. Do not install both distributions together: they share the deprecated stdio shim and `study-migrate` launcher, so uninstalling the old distribution afterward removes shared files. See the [README upgrade sequence](../../README.md#upgrade-from-the-former-distribution).

Update current Host registrations to `cognivault` and the launch module to `cognivault.transports.mcp_stdio`. The Codex helper migrates only exact recognized helper-generated old configurations; custom registrations need manual changes. Keep private backend locations and capabilities. The deprecated stdio startup module remains temporarily available and reports the same canonical server identity.

## Data safety

The identity transition requires no data migration, History re-ingestion, re-normalization, or canonical rewrite. StudyVault remains the sole authoritative Study source; raw evidence and provenance remain distinct from derived canonical History. Historical `study_system` provenance and named isolated servers are preserved.

The verifier correction required no production data repair. The old verifier's 1,265 version mismatches were reproduced on an isolated Gateway restore with matching source and canonical digests; each affected historical message evidence version matched its owning view. Production validation was read-only.
